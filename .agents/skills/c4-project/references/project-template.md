# Структура и шаблоны проекта

## Структура (фиксированная)

Проект — это раздел `<slug>` в каждом слое мозга плюс паспорт в `projects/<slug>/`:

```
raw/<slug>/                        сырьё проекта: всё, что человек прислал в чат, дословно, с шапкой
wiki/<slug>/{sources,concepts,entities,syntheses}/   знания проекта
plans/<slug>/                      планы (c4-plan)
outputs/<slug>/                    результаты
projects/<slug>/
├── project.yaml   метаданные — единственное место для статуса, дат, тегов, ссылок
├── README.md      суть проекта для человека и агента, без фронтматтера
├── interview.md   дословные вопросы и ответы (только дописывать)
├── decisions.md   журнал решений (только дописывать)
├── log.md         хронология работы по проекту (только дописывать)
├── notes/         рабочие заметки, черновики
└── assets/        рабочие файлы проекта: логотипы, макеты, выгрузки
```

Правила:
- В корне паспорта — только эти пять файлов и две папки. Пустые папки держатся через `.gitkeep`.
- Подпапки внутри `notes/`, `assets/`, `outputs/<slug>/` — по смыслу, kebab-case латиницей (`assets/brand/`, `outputs/<slug>/landing-v1/`). Глубже двух уровней без нужды не уходить.
- Имена файлов: kebab-case латиницей; датированные — с префиксом `YYYY-MM-DD-` (`notes/2026-11-09-call-with-client.md`).
- Знания (выводы из статей, видео, разговоров) — через «запомни»: `raw/<slug>/` → `wiki/<slug>/`. Общее для нескольких проектов — в `wiki/general/`, проект ссылается через `project.yaml → wiki`.

## `project.yaml`

```yaml
slug: <slug>                 # совпадает с именем папки
title: <Название>
summary: <цель одной фразой>
status: active               # active | paused | done | dropped
created: YYYY-MM-DD
updated: YYYY-MM-DD
review_by: YYYY-MM-DD        # следующий пересмотр по выбранному ритму
review_every: 2w             # 1w | 2w | 1m — ритм из блока I интервью
deadline: null               # YYYY-MM-DD или null
tags: []
people:                      # кто участвует, кроме самого человека
  - name: <Имя>
    role: <заказчик, партнёр, подрядчик…>
repos: []                    # пути или URL репозиториев с кодом проекта
links: []                    # внешние ссылки: сайт, доска задач, облачная папка
wiki: []                     # страницы из других разделов: wiki/general/concepts/x.md
services: []                 # подключённые сервисы: - {name: amoCRM, via: context4}
```

Чего человек не дал — `null` или `[]`, не выдумывать. YAML должен быть валидным: строки с `:` или `#` бери в кавычки.

## `README.md`

```markdown
# <Название>

> <Цель одной фразой>

## Зачем
<Боль/желание, почему сейчас, настоящая мотивация. 2–4 предложения.>

## Цель и критерий готовности
- **Цель:** <конкретный результат>
- **Готово, когда:** <проверяемый критерий>
- **Минимум, который устроит:** <...>
- **Срок:** <дата и насколько он жёсткий>

## Для кого
<Пользователи/заказчик, конкретные люди, кто принимает решения.>

## Где мы сейчас
<Что уже есть, что пробовали, аналоги.>

## Ограничения
- Время: <...>
- Бюджет: <...>
- Навыки/люди: <...>
- Нельзя: <...>

## Не делаем
- <...>

## Риски
| Риск | Вероятность | Что делаем заранее |
|---|---|---|
| <...> | высокая/средняя/низкая | <...> |

**Бросаем, если:** <критерий остановки>

## Next actions
- [ ] <первый шаг — что делаем в ближайшие 1–2 дня>
- [ ] <...>
```

Пропущенные поля — `❓ не выяснено`, размытые ответы — с пометкой `⚠ размыто`; каждое такое поле — пункт в Next actions «добить: <поле>». Статус, даты, ссылки и людей в README не пиши — они в `project.yaml`.

## `interview.md`

```markdown
# Интервью: <Название>

## YYYY-MM-DD — заведение проекта

**В:** <вопрос как задан>
**О:** <ответ человека дословно, без правки>

### Зеркало
<Пересказ, который человек подтвердил, и его поправки.>
```

При `review` дописывай раздел `## YYYY-MM-DD — пересмотр` в конец. Старые разделы не меняй.

## `decisions.md`

```markdown
# Решения: <Название>

## YYYY-MM-DD — <решение коротко>
- **Решили:** <что именно>
- **Почему:** <причина>
- **Варианты:** <что ещё рассматривали и почему нет>
- **Пересмотреть, если:** <условие, при котором решение поднимаем снова>
```

Новые решения — в конец. Отменённое решение не стирается: новая запись «отменяем решение от YYYY-MM-DD, потому что…».

## `log.md`

```markdown
# Log: <Название>

## [YYYY-MM-DD] project | new <slug>
Проект заведён по интервью.
```

Формат как в корневом `log.md`: `## [YYYY-MM-DD] операция | что сделано`, ниже 1–3 строки деталей и ссылки на изменённые файлы. В корневой `log.md` по той же работе — одна строка со ссылкой на проект.
