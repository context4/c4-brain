# Шаблоны

## `projects/<slug>/README.md`

```markdown
---
title: <Название>
type: project
status: active            # active | paused | done | dropped
created: YYYY-MM-DD
updated: YYYY-MM-DD
review_by: YYYY-MM-DD     # дата следующего пересмотра по выбранному ритму
deadline: YYYY-MM-DD      # или пусто, если срока нет
tags: []
---

# <Название>

> <Цель одной фразой>

## Зачем
<Боль/желание, почему сейчас, настоящая мотивация. 2–4 предложения.>

## Цель и критерий готовности
- **Цель:** <конкретный результат>
- **Готово, когда:** <проверяемый критерий>
- **Минимум, который устроит:** <...>
- **Срок:** <дата и насколько он жёсткий>

## Для кого
<Пользователи/заказчик, конкретные люди, кто принимает решения.>

## Где мы сейчас
<Что уже есть, что пробовали, аналоги.>

## Ограничения
- Время: <...>
- Бюджет: <...>
- Навыки/люди: <...>
- Нельзя: <...>

## Не делаем
- <...>

## Риски
| Риск | Вероятность | Что делаем заранее |
|---|---|---|
| <...> | высокая/средняя/низкая | <...> |

**Бросаем, если:** <критерий остановки>

## Знания и ресурсы
- Вики: [[...]]
- Источники: [[wiki/sources/...]]
- Внешнее: <ссылки, люди>

## Планы
_Пока нет. План реализации — скилл `c4-plan`._

## Next actions
- [ ] <первый шаг — что делаем в ближайшие 1–2 дня>
- [ ] <...>

## История
- YYYY-MM-DD — проект заведён (интервью: [interview.md](interview.md))
```

Поля, которые человек пропустил, пиши как `❓ не выяснено`; размытые ответы — с пометкой `⚠ размыто`. Каждое такое поле — отдельный пункт в Next actions: «добить: <поле>».

## `projects/<slug>/interview.md`

```markdown
# Интервью: <Название>

## YYYY-MM-DD — заведение проекта

**В:** <вопрос как задан>
**О:** <ответ человека дословно, без правки>

**В:** ...
**О:** ...

### Зеркало
<Пересказ, который человек подтвердил, и его поправки.>
```

При `review` дописывай новый раздел `## YYYY-MM-DD — пересмотр` в конец. Старые разделы не меняй.
