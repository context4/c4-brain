# Второй мозг — схема

Система по паттерну Андрея Карпатого «LLM Wiki»: знания компилируются один раз в вики и поддерживаются актуальными, а не пересобираются из сырья на каждый запрос. Ты (LLM) — поддерживающий вики. Человек — куратор источников, задаёт вопросы и ведёт проекты.

Эта папка — общий мозг для любого агента: Codex, Claude Code, Cursor, Gemini CLI и других. Правила живут здесь, в `AGENTS.md`; `CLAUDE.md` и `GEMINI.md` только подключают этот файл. Скиллы лежат в `.agents/skills/` (`.claude/skills` — ссылка туда же).

## Скиллы
Каждый скилл — папка `.agents/skills/<name>/` с файлом `SKILL.md` (открытый формат Agent Skills). Если твой агент подгружает скиллы сам — пользуйся ими как обычно. Если нет — **когда задача подходит под скилл, сначала прочитай его `SKILL.md` целиком и следуй ему**, а нужные `references/` открывай по ссылкам из него.

| Скилл | Когда |
|---|---|
| `c4-project` | Человек просит завести, пересмотреть или закрыть проект. Только по прямой просьбе. |
| `c4-brainstorm` | Задача мутная или есть несколько путей: зафиксировать результат, ограничения, критерии и выбрать подход. |
| `c4-plan` | Работа требует фаз, архитектуры или плана. |
| `c4-cook` | Реализовать план из `plans/` по фазам или маленькую понятную правку. |
| `c4-scout` | Найти нужные файлы в мозге или репозитории перед работой. |

Обычный путь большой задачи: `c4-brainstorm` → `c4-plan` → `c4-cook`; `c4-scout` — внутри любого шага. Человек может назвать скилл как угодно («c4-plan», «/c4-plan», «сделай план») — это один и тот же скилл.

## Три слоя
1. `raw/` — сырые источники. **Неизменяемы**: читаешь, но никогда не редактируешь. Обработанное переносишь в `raw/_processed/` только по команде человека.
2. `wiki/` — твой слой. Markdown-страницы, которые ты создаёшь, обновляешь и перелинковываешь. Человек их только читает.
3. Эта схема (`AGENTS.md`) — правила. Вы дорабатываете её вместе.

Дополнительно: `projects/` — хабы проектов, `plans/` — планы реализации, `outputs/` — результаты (отчёты, слайды, видео).

## Структура
```
raw/{articles,videos,transcripts,docs,images}   входящие материалы
wiki/sources/     по одной странице на источник (саммари + ссылка на raw)
wiki/concepts/    идеи, темы, методы
wiki/entities/    люди, компании, инструменты, продукты
wiki/syntheses/   сохранённые ответы, сравнения, анализ
projects/<name>/  README.md (зачем, цель, критерий готовности, статус, next) + interview.md
plans/            планы реализации (скилл c4-plan)
outputs/          сгенерированные материалы (не источник знаний)
index.md          каталог всех страниц вики и активных проектов
log.md            хронология операций (append-only)
```

## Формат страницы вики
Имена файлов: kebab-case, латиницей. Фронтматтер:
```yaml
---
title: ...
type: source | concept | entity | synthesis
tags: []
sources: []      # ссылки на wiki/sources/* или raw/*
projects: []     # связанные проекты
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
Ссылки между страницами — `[[wiki-links]]`. Утверждения подкрепляй ссылкой на источник. Противоречия не прячь — помечай `> ⚠ Противоречие:`.

## Операции
**Ingest** (человек кладёт файл в `raw/` и говорит «обработай X»):
1. Прочитай источник, коротко обсуди ключевые выводы с человеком.
2. Создай `wiki/sources/<slug>.md`.
3. Обнови или создай затронутые concept/entity-страницы (один источник часто трогает 10–15 страниц).
4. Обнови `index.md`. Если источник относится к существующему проекту — добавь ссылку в его `projects/<name>/README.md`.
5. Добавь запись в `log.md`: `## [YYYY-MM-DD] ingest | Название`.

Видео и аудио: сначала транскрипт в `raw/transcripts/` любым доступным инструментом, затем обычный ingest.

**Query**: читай `index.md`, затем нужные страницы, отвечай с цитированием. Ценный ответ сохраняй в `wiki/syntheses/` и логируй (`## [дата] query | Вопрос`).

**Lint** (по запросу «lint»): противоречия, устаревшие утверждения, страницы-сироты, упомянутые но не созданные концепты, отсутствующие перекрёстные ссылки, пробелы данных, проекты без движения дольше их `review_by`. Лог: `## [дата] lint | ...`.

## Проекты
Проект — это то, ради чего человек вообще копит знания. Поэтому проект заводится осознанно и с полным контекстом.

- **Проекты никогда не создаются автоматически.** Ни при ingest, ни при query, ни при планировании. Если материал похож на новый проект — максимум предложи одной строкой: «Похоже на отдельный проект. Завести через `c4-project`?» — и жди ответа.
- Создание, пересмотр и закрытие проекта — только через скилл `c4-project`. Он проводит интервью и не создаёт проект, пока не выяснит главное: зачем, цель, критерий готовности, первый шаг.
- Знания живут в `wiki/`, проект только ссылается на них. Активные проекты перечислены в `index.md`.
- Ответы человека из интервью сохраняются дословно в `projects/<name>/interview.md` — это самый ценный контекст проекта, не перефразируй его.

## Планы
Планы реализации делает скилл `c4-plan` в `plans/<YYMMDD-HHMM>-<slug>/`. План, относящийся к проекту, ссылается на него (`project:` во фронтматтере) и появляется в разделе «Планы» README проекта. Скилл планирования проект не создаёт.

## Правила
- Никогда не правь `raw/`.
- Не удаляй страницы и проекты без ОК человека — помечай `status: deprecated` (страницы) или `status: dropped` (проекты).
- Каждая операция заканчивается обновлением `index.md` и `log.md`.
- Не выдумывай за человека: чего не знаешь о его целях и проектах — спроси или пометь `❓ не выяснено`.
- Масштаб: до ~100 источников хватает `index.md`; дальше предложи локальный поиск (например, qmd).
